Pitfall: acceptance criteria written with greps and line-count caps were wrong twice in this goal.
1. A grep for a stale path matched prose the task was forbidden to edit (criteria-defect; required user-approved scope widening).
2. A `git diff --stat` cap assumed edited lines count once; --stat counts each edited line as -1/+1, so 4 edited lines = 8.
Also: a bootstrap answer written as a bare table row rendered as a stray paragraph because the template places it above the table header — render-check (pandoc -f gfm) emitted docs.
How to avoid: during pre-flight, run every grep criterion against the WHOLE target scope (not just link lines), compute --stat caps as 2x edited lines (+ net growth), and read the template context of each bootstrap id before answering.
